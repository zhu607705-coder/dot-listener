# vivo X200 Ultra：端侧采集与转写工程计划

## 已有源码

`MainActivity` 负责显式操作与授权；`RecordingService` 运行麦克风前台服务；`EncryptedSegments` 保存约 30 秒加密 PCM 段；`CapturePolicy` 负责可独立测试的睡眠逻辑。

本版未提供 APK，未在 X200 Ultra 上运行。独立 Kotlin 检查只覆盖不依赖 Android 的策略函数。

## ASR 接入路线

采用 sherpa-onnx + SenseVoice 作为首个评估候选。官方提供对应 Android 示例和量化模型路径；候选支持中文等语言，不构成该手机全天性能保证。[S6](SOURCES.md)

```text
AudioRecord PCM
    ├── 加密归档（连续）
    └── 环形缓冲 → VAD 窗口 → 解密/内存 PCM → SherpaAdapter → TranscriptFragment
                                                        │
                                                        └── 持久手机文本 Outbox
```

## 生命周期

启动前需要可见用户动作、录音告知确认、麦克风授权。前台服务必须显示通知。不得用无障碍服务冒充普通应用以抢麦，不监听电话内容，不绕开系统麦克风提示。系统共享输入行为依据见 [S1、S2](SOURCES.md)。

`START_NOT_STICKY` 是本版有意选择：进程消失后，不自行恢复麦克风。用户再次确认后续录。将来要研究全自动恢复，必须先列出不同系统版本允许的合法启动路径。

睡眠规则使用手机本地时区。夏令时、跨时区旅行和手动改钟要测试；采样覆盖统计应使用单调时钟，不能只用墙钟差。目前只有窗口策略，不包含完整覆盖日志。

## 加密格式

文件头为 `DL01`，接 12-byte IV，再接 AES-GCM 密文和认证标签。AAD 固定为 `DL01|16000|1|s16le`。密钥驻留 Android Keystore；应用卸载可能使数据不可解密，不能承诺卸载后恢复。

`.part` 只在成功关闭加密流、生成认证标签后改名。崩溃遗留片段应隔离并显示缺失，不能去掉扩展名假装修好。删除、保留期限、存储压缩与解密回听在下一阶段实现。

## 构建基线

AGP 8.9.2 / Gradle 8.11.1 / JDK 17 / compileSdk 35 / targetSdk 35 / minSdk 29 / Kotlin 插件 2.1.10。选择固定开发基线，不声称它是最新配置或满足未来应用商店发布政策。[S7](SOURCES.md)

当前缺少 Android SDK 构建与真机环境；先在 Android Studio 同步和编译，再做设备验证。不能把 JVM 策略测试通过写成 Android 编译通过。


## 2026-10-22 静态审查修正

停止期间阻塞读取可能返回负错误码或抛异常，不能因此把用户暂停或麦克风中断覆盖为 ERROR。`readWhileRunning` 在读取前后及异常路径检查运行状态，JVM 检查覆盖取消与真实故障。服务使用锁串行启动/停止/释放，并以 `stopSelf(startId)` 防止旧任务停止新请求。这些是源码修正和 JVM 证据；未执行 Android SDK 构建、立即启停真机测试或熄屏验收。
