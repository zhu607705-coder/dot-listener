# HUAWEI WATCH GT 6 Pro 音频入口：先验证，再绑定架构

华为官方兼容性页列出 GT 6 系列录音机及所需版本，包含与兼容 Android 手机配对的情况。但这不是第三方麦克风、文件导出或 vivo 自动同步 API 文档。[S9](SOURCES.md)

## 能力门 G0

必须实际回答：**手表录制的一段声音，能否通过用户有权使用的稳定通道取得原音频，并在 vivo X200 Ultra 上程序化处理？**

| 探针 | 记录内容 | 可以支持的结论 |
|---|---|---|
| 系统录音 | 型号、地区、固件号、最长单次表现 | 仅证明系统应用自身能录 |
| 手工导出 | 格式、手机端入口、是否仅特定手机可用 | 证明某一种导出流程，不代表自动化 |
| 第三方应用权限 | 当前 SDK 文档、申请条件、可复现工程 | 才能讨论自研手表收音 |
| 文件取得 | 原文件校验、持续多个片段、锁屏场景 | 稳定性，不用截图代替文件 |
| 连续与恢复 | 录制上限、轮转、断连、连接恢复 | 才能讨论全天方案 |

## 分支决策

A. 有稳定合法音频入口：实现 `WatchAudioSource`，转写仍在手机。

B. 只有手工导出：作为人工导入实验入口，不宣传“全天自动”。

C. 无法取得原音频：保留手机麦克风主线；手表遥控功能也须独立确认开发/通信能力，不能写成已支持。

## 不采用的办法

不刷机，不利用漏洞绕过签名，不读取无权访问的运动健康私有目录，不把蓝牙通话存在当作开放音频流证明。

当前所有探针结果：**未实机验证**。此文档是实验记录模板，不是设备支持声明。
